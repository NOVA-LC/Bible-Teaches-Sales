# Use skills where they improve this task

This is the portable Watchtower workflow projection. Personal skills stay in
their host and are loaded only for an applicable task. This file does not install
skills, create agents, grant permissions, or change the current quality bar.

## Preparation defaults

| Working principle | Application | Observable enforcement |
| --- | --- | --- |
| Intent preservation | Preserve the operator's approved voice, depth and emotional effect; answer each paragraph at its place in the article. | Complete immutable plan, future-point reservations and independent paragraph-fit review. |
| Plan before prose | Allocate types, mechanics, domestic scenes and distinctive moves before drafting. | Existing article gates also run on the plan; Type B needs supplied experience, Type H needs saved research. |
| Evidence before confidence | Distinguish exact quotations, paraphrases and inferences. Research can inform an insight; an analogy cannot establish a historical fact. | Saved context and policy are fingerprinted and passed to writer, reviewer and repair. |
| Remember why | Preserve the exact defect that caused a repair and the conditions for resuming. | Persistent events, accepted hashes and read-only status/next action. |
| Verification before completion | Review real support, continuity, listener impact and exact accepted wording. | Current review hash, complete coverage, existing gates, bounded repair and comment-only export. |

The installed `intent-contract`, `principled-problem-solving`, `optimal-path`,
`remember-why` and `verification-before-completion` provide these disciplines.
Use the installed source when needed; this table is a scoped projection, not a
replacement copy of the skills. The run's full article, plan, approved references
and context are the concrete inputs. A skill name or completed metadata field is
never a quality verdict.

## Current authority and voice

For Work/chat Watchtower preparation, `../AGENTS.md`, `RUNBOOK.md`,
`prompts/comment_agent.md`, its type contracts and `gates.py` define the current
production rules. The older production settings in `../voice/drafting-recipe.md`
are historical for this workflow. Its voice craft remains useful. Current rules
are 130–200 words, every question-bearing paragraph, type-aware mechanics, the
existing quotas/caps, one consolidated independent review and one targeted repair
per failed paragraph. Preserve the full-answer underline doctrine separately.

The shared core referenced by the type documents is included in
`prompts/comment_agent.md`. Tools named in that SDK prompt describe SDK execution;
Work uses its actual available research tools and saves equivalent source evidence
in context. Do not try to invoke nonexistent SDK tools in a chat preparation.
An existing verified research result may be reused; the writer need not refetch it
just to claim it personally called a particular tool.

Never treat a worked first-person example as evidence that it happened to the
operator. Type B requires a supplied, traceable experience. A context record is
not proof of authenticity: the independent reviewer checks its actual provenance.
Teaching methods may clarify a cause-and-effect connection or an illustration's
limits; they must not shorten, standardize or replace the approved comment voice.

## Conditional tasks

- For code changes, use applicable planning, debugging, test-first development,
  isolated branch and actual independent code-review skills. Review the changed
  behavior; do not run a fresh development workflow for each paragraph.
- For access failures, use `github-access-repair` and its direct installation
  link, then resume the actual authorized operation. Public reads do not prove
  write access. A new repository does not grant unlimited access.
- For explicit council, expert or Coach requests, read that skill and satisfy its
  real prerequisites. Never invent participants, scores or expert endorsements.
  A general inventory request does not make every optional panel a default cost.
- For a requested document, chart, presentation, image or site, load that output
  skill at packaging time. Packaging preserves accepted comment text.
- For sales lessons, follow the root sales contract; sales voice and persuasion
  skills are scoped there. They do not govern congregation comments.
- External messaging, company reports, pet workflows, profile curation and plugin
  installation activate only for their actual task. Inventorying them grants no
  authority to send, publish, connect accounts or spend money.

Inspect `status` before restarting. Checkpoint counts measure saved operations,
not model calls, tokens, quota or dollars. Prove savings with an actual preparation
and retain uncertainty until measured. Keep all private inputs and run files out
of Git, and keep original runs when a new policy invalidates their fingerprints.
